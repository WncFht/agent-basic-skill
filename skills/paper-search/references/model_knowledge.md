# 模型知识补充协议

`model_knowledge` 是可选的 Agent 侧补充来源，没有对应连接器，不占用 CLI 参数。它的定位:API 检索在两种可预见的情况下高精度但低召回——

1. **奠基性的老论文**:从业者人人会引，但关键词搜索搜不到 (比如查一个新变体时的原始 BERT 或 ResNet 论文)。
2. **跨学科经典**:它们所在的 venue 恰好是 API 索引较差的。

模型回忆与 API 互补，把"大家都知道"但新鲜关键词查询不一定返回的论文捞出来。只在奠基性或跨学科覆盖明显缺失时使用。

## 填充步骤

CLI 运行完成后：

1. 围绕查询主题回忆你所知的内容。
2. 从训练数据中列出最多 10 篇符合查询与年份区间的论文，含：标题、主要作者、年份、venue，以及一句相关性理由。
3. 用在线来源核实准确的标题、年份、venue 和规范 URL。
4. 与 API 结果去重——如果论文已出现在任何 API 来源里，不要再放到 `model_knowledge` 下。
5. 核实失败就舍弃该候选。空的补充是正确答案。

## 为什么诚实至关重要

幻觉论文标题是这类任务经典的 LLM 失败模式。一条伪造的"Smith et al., 2023, NeurIPS"在 Markdown 表格里和真的一条看起来一模一样，用户无从分辨。这个来源的意义是打捞 API 漏掉的**真实**论文——不是凑数。如果回忆不出 5 篇有把握的，就返回更少;空的模型知识小节完全可以，而且诚实。

## 展示格式

使用与其他来源相同的表格布局，并链接用于核实的规范 URL;把"Citations"列换成"Notes",因为该补充不采集被引数：

```
### Model Knowledge(N 篇已核实)

| #   | Title       | Year | Venue   | Notes |
|-----|-------------|------|---------|-------|
| [1](https://scholar.google.com/scholar?q=Title) | Title here | 2018 | NeurIPS | 奠基作;X 方向的近期工作普遍引用 |
| [2](...) | Title here | 2024 | ICLR | 已核实的奠基性补充 |
```
