# Compression Rules

Deliver the result first, then only the evidence, action, or risk the user needs.

## Keep

- Result before background.
- One short paragraph per job.
- Evidence only when it supports the result.
- Actions only when they were done or are required next.
- Risk only when something is truly unverified, blocked, external, or behaviorally risky.

## Remove

- Task restatement.
- Polite prefaces.
- Repeated conclusions.
- Generic caveats.
- Full reasoning translated into Chinese.
- Extra suggestions that do not follow from the current task.
- Fixed two-section or report-style templates for small answers.

## Structure

Use no heading for small answers. Use short headings only when the answer has multiple distinct parts, such as result, verification, and risk.

## Final Check

Before final delivery:

1. Can the user see the result immediately?
2. Is any sentence only explaining your thinking process?
3. Does deleting the last sentence make the answer better?
4. Does the final sentence add useful state, evidence, action, risk, or a concrete question?
