# VLM 语义评审 — 机器审计够不着的最后一层

机器审计（`check_audit.py` / `fv.audit`）只背书两类事实：几何不变量（盒全等、铺满、不碰撞、不穿线）与数据层不变量（出限、基线、log 非正数）。它管不了「图说了什么 vs 画了什么」——有实测活例：顶部主张与曲线证据矛盾，几何审计 7 盒 2 线全绿，语义评审仍判 fail。这类语义层造假是固有盲区，只能靠「另一双眼睛」。

`scripts/vlm_judge.py` 把这双眼睛工具化：生成一份 markdown 评审单（意图摘要 + 六条 checklist + 可直接喂给任意 VLM 的提示词），可选直接调 `claude` 后端把回复附进报告。它是 advisory——**不是审计**。

## 用法

```text
python3 <skill>/scripts/vlm_judge.py fig.png                        # 评审单落 fig.vlm-judge.md
python3 <skill>/scripts/vlm_judge.py fig.png --intent NOTES.md      # 带作者意图，评「主张一致性」才有靶子
python3 <skill>/scripts/vlm_judge.py fig.png --intent fig.spec.json # spec 自动抽 meta.ledger/caption + series/panels 名单
python3 <skill>/scripts/vlm_judge.py fig.png --backend claude       # PATH 有 claude 时实际调用并附回复
python3 <skill>/scripts/vlm_judge.py fig.png --out /tmp/review.md   # 改产物落点
```

工作流位置（opt-in）：渲染 → 机器审计零错误 →（用户明确要求时）**vlm_judge** → 人目检 PNG → 交付。它插在「审计全绿」与「交付」之间——审计保证图没画错形，judge 追问图有没有说错话。**默认不跑**——仅在用户明确要求语义/VLM 评审时执行 `--backend claude`（一次一图、不进迭代循环）。

- `--intent` 接任何声明「图想论证什么」的文本：台账、spec.json、NOTES.md、tex 源、`.audit` 都行；`.json` 按 spec 抽 `meta.ledger`/`meta.caption` 及 series/panels 名单，其余按纯文本截取**文件头部**（上限 ~8000 字符）——台账/主张这类评审靶子要放在文件头，只写在尾部的关键声明进不了评审单。不给 intent 时只按图面评审，评审单会列出同目录检测到的候选 intent 来源（NOTES.md / 同名 spec/tex/audit）。
- `--backend none`（默认）不调用任何模型：评审单里附整段可复制提示词，调用者自己连同图片喂给任意 VLM。`--backend claude` 在 PATH 有 `claude` 时执行 `claude -p <提示词> <图>` 并把回复写进「VLM 回复」节；调用失败/超时（`--timeout`，默认 300s）降级为只产评审单并打 `warn backend:`。
- 输出遵守统一行约：`warn <rule>: <msg>`（如非常见图片后缀、intent 读取失败、backend 未产出回复），干净运行打 `ok: <file>`。

## Checklist 判定指引

每条先按具体问题逐项核对，再给一个三级判定；证据一栏写图中具体位置（哪个面板、哪条曲线、哪行字），不接受「看着还行」。

| 条目                 | PASS                                           | CONCERN                                        | FAIL                                                            |
| -------------------- | ---------------------------------------------- | ---------------------------------------------- | --------------------------------------------------------------- |
| 1. 主张—数据一致性   | 每条主张都有图面证据直接支撑，显眼现象都被解释 | 个别主张缺直接证据但无反证；简化声明有但不醒目 | 主张与曲线/结构证据矛盾，或断言了图中根本不存在的关系——拒收     |
| 2. 标签可读性        | 交付尺寸下全部文字可读、记号全部有定义         | 个别标签偏小/偏挤但可辨认；非关键缩写未展开    | 文字裁切/截断/溢出，关键记号无定义，数学渲染出豆腐块            |
| 3. 编码通道可辨识度  | 色相两两可辨、一色一义、第二通道单调对应       | 色对明度接近但在语境中可区分；轻微超预算有声明 | 同色两义、两色近到不可分、明度/线型与声称语义倒挂               |
| 4. 阅读顺序          | 动线顺论证推进，流向与连接器一致               | 局部需要停顿找入口，但无误导性动线             | 视线被迫来回跳、箭头方向与语义流向相反、面板顺序不可辨          |
| 5. 未埋点碰撞风险    | 无未审计对象的压叠擦碰                         | 有贴近但未压叠的紧凑处，可人工确认放行         | 未埋点文字压线/压框/压字、元素被裁掉半个、白衬底盖住关键信息    |
| 6. 图—caption 一致性 | 标识行/含义框恰描述所画，与正文 caption 互证   | 描述略粗但无错；caption 与图面措辞风格差异     | 标识行说了图里没有的、漏了图里关键的，或与正文 caption 各说各话 |

总判：全 PASS → PASS；任一 FAIL → FAIL；其余 → CONCERN。FAIL 与未消化的 CONCERN 都按「交付前检查第 6 条」拒收重画——judge 不拦人，但结论留着不处理等于没评。

## 与审计的边界

- **advisory，永不 block**：`vlm_judge.py` 没有 exit 1——评审发现再多问题也 exit 0，退出码只表达「评审单是否生成」（exit 2 仅用于图/intent 不存在等用法错误）。它永不 emit `ERR` 行。
- **不进渲染产物语义**：评审单不是 `ok:`/`artifacts:` 管的渲染产物，`render.py` 的审计契约不覆盖它；VLM 说「FAIL」不会让渲染管线变红——判的是图，不是构建。
- **不替代机器审计**：几何/数据不变量照旧由 `check_audit.py`/`fv.audit` 背书；judge 的第 5 条「未埋点碰撞」专查审计盲区，不是把埋点检查再做一遍。
- **不替代人目检**：交付前检查第 5 条（原尺寸 + 缩略图目检）仍由人做。judge 的价值是 prompt 固化六类问题 + 外部视角，VLM 的每条 CONCERN/FAIL 都要人工复核后处理——它出意见，人做裁决。
- **不是 pass 证明**：评审单全 PASS 只说明这次没被问倒，不等价于语义正确；与审计「零错误且确实跑过」同理，「评审过」要求真的把图喂给了眼睛（人或 VLM），不是生成一张空评审单。
- **评审单必须回填**：verdict/证据栏空白的评审单按未评审处理——`vlm_judge.py` 只负责产出带靶子的单子，逐条判定 + 图面证据是调用方的义务（六条全部写 `PASS/CONCERN/FAIL` + 定位证据，或 `--backend` 实际调用拿到回复）。交付检查见到空白单退回补评，不接受「单子生成了所以评过了」。
- **judge 也有盲区**：评审是全图扫描但非穷举——可机检的缺陷类它照样漏（k3 语料实锤：含义框印 `vteal`/`vviolet` 等内部调色板 token，judge 只命中 4/9 处，余 5 处含一张 PASS 图，靠 `pdftotext fig.pdf - | grep` 兜底扫出）。凡是能用一行 grep/脚本穷尽的泄漏类，别只靠眼睛——judge 问的是「图上还有什么不对劲」，不是替你跑正则。
