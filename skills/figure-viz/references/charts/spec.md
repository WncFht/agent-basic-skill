# Figure spec

`spec.json` 把「一张图」描述成纯数据：`render(spec) -> Figure` 是 spec 与其引用 CSV 的纯函数。数值求解、模型加载、原始实验状态全部留在脚本侧（glue），spec 只消费聚合表——这就是「先聚合出 agg 表、再由 `make_figure(agg)` 画图」那条边界的机器化。

两条输入路径同构：

- **JSON**：`render_mpl.py SPEC.json [--outdir DIR] [--dpi N] [--no-audit]`，数据经 `data.*.csv` 引用落盘聚合表；
- **Python**：`fvspec.render(spec_dict, base_dir=spec_dir)`，返回带 `fvspec_report`（`{warnings, saved, audit_kwargs}`——audit_kwargs 直接展开进 `fv.audit`）的 Figure；数据集同样写在 `spec["data"]` 里，`{fields,map}` 形态可接 tuple-key 聚合 dict（JSON 无 tuple 键，仅此形态是 Python-only）。

```text
render: uv run --with matplotlib --with numpy python <skill>/scripts/render_mpl.py fig.spec.json                # → spec.output.path（缺省则写 stem.png/.svg/.pdf）
        uv run --with matplotlib --with numpy python <skill>/scripts/render_mpl.py fig.spec.json --outdir imgs/ # CLI 覆盖产物目录
        uv run --with matplotlib --with numpy python <skill>/scripts/render_mpl.py fig.spec.json --no-audit     # 跳过 lint 打印与 render audit
```

退出码：spec 校验错误 2；审计输出统一 `ERR <rule>: <msg>`/`warn <rule>: <msg>` 格式，存在 error 级才以 1 退出，warn 级不阻断（`--no-audit` 关闭）；lint 警告打印 `warn lint:<name>: <msg>`。

**实现现状**（v1 渲染器）：grid/matrix/spans 三种布局、xy/radar/donut 面板、line/pred/band/scatter/bar/hist/ecdf/kde/box/violin/heat/contour/quiver/image/sankey/sig/ref/span/note/donut 系列已实装；`layout.rows`/`cols` 边默认（ylabel 归左缘、xlabel 归底缘）与 matrix 的 `$row`/`$col` 模板展开、strip margin（`strips` 管位置）、spans 的 `map` 跨格与 `bind` 边际轴配对（side 面板分布 kind 用 `dir:'h'` 横置）、sankey 的 `flows` 字面流与 `dir:'v'` 竖排、bar 瀑布三件套（`bottom`/`connect`/`labels`）、contour 类别标签轴与 `clabel.manual` 均可用。

## 何时用 spec / 何时用逃生舱

| 场景                                                               | 路径                                        |
| ------------------------------------------------------------------ | ------------------------------------------- |
| 标准实验图：折线 + band + 参考线 + 分类散点，≤8 格网格（1xN、2x2） | spec                                        |
| 方法×样本图版（image-plate：全 image 面板网格放宽到 64 格/边 16）  | spec（`image` 系列 + `badge` 行级角标）     |
| 面板里要 annotate 手术、inset、逐点 mask、gantt、自由 twin 轴      | 该面板 `panels.*.raw`（其余面板照常 spec）  |
| 整图自由构图（机制示意图、多图混排）                               | 纯 matplotlib + `fvstyle` token，audit 照跑 |
| 数值/求解/模型加载/多段 CSV/env 缓存                               | 永远 glue：先算出聚合表再进 spec            |

`raw` 签名 `f(ax, ctx)`，`ctx={spec, panel, data, theme, fv, ax, ax2, fig, colors, panel_axes}`（`ax2`/`fig` 为 None/图对象，给逃生舱直接够到 twin 轴与画布；`panel_axes` = {面板 id: Axes} 一等快照——调用时全部面板 axes 已建好，跨面板取轴按 id 直查，不必按 `fig.axes` 创建序猜（声明序 = panels 序、twin 紧随宿主）），在该面板 spec 化收工后最后调用——series、axis、frame、grid、title、panel legend 全部落位之后，raw 对面板 axes 有最终发言权（隐藏 spine、手摆刻度不会被 apply_* 覆盖）；跨面板收口（共享轴 label_outer、figure legend、layout）仍在其后。raw-only 面板合法，一张图可混排 spec 与 freeform 面板，audit 不受影响。`ctx['fv']` 就是 fvstyle 模块本体——raw 里 `color='vink'` 这类 token 字面量不走 spec 色解析，取色用 `ctx['fv'].HUES[...]`/`NEUTRALS[...]`（extend 名与 `*_edge` 走 `ctx['colors'].token('vink', lambda n,m: None)`——lint 是必传位参，no-op 即可）；`ctx['data']` = `{数据集名:[行dict]}`，CSV 值已过 int/float/bool 强转。渲染期间 spec 所在目录自动进 `sys.path`，旁挂 `helper.py` 直接写 `'helper:func'`；子模块与包路径照常 `pkg.mod:func`。旁挂 helper 被 import 后产物目录留 `__pycache__/`（与 fvlocate vendored 副本同副作用），交付前自清。

数据静默丢弃的反面约定：`missing-rows`（必需列在部分行缺值——报「n/total 行将被绘制丢弃」）、`unknown-field`（by/err/bottom 等引用了数据集中整列缺失的字段）、`where-field-missing`（where/panel.where 引用字段在系列 dataset 整列缺席——点名 sid+ 字段 + 来源，明示该从句会滤空全部行）、`axis-ignored`（类别轴上的 `ticks`/`tick_labels`/`scale` 归 kind 层所有故忽略——bar/box/violin 的类别 x、heat 的双轴、scatter 类别 y 的 y 轴；`tick_labels` 无 `ticks` 锚点被忽略；`lim` 在类别轴上仍生效——按类别序号定限）、`note-outside-axes`（纯 `data` 坐标的 note 落点在 axes 外被 `annotation_clip` 静默吃掉——units 混合坐标不 clip 故不报；锚点在轴内、墨迹越 spine >2pt 的对侧情形归 audit `text-spills-axes`）、`sig-outside-axes`（sig 括号梁出 y 窗或顶沿余量装不下星号文本——clip_on 关闭的括号不哑火、只是画出轴外）、`occluded-by-heat`（系列 zorder 追不上同面板的不透明覆盖面——heat 的 pcolormesh 或 contour 的 contourf（mode `fill`/`fill+lines`）——渲染上被完全盖住，与列表序无关只按 zorder 判定）、csv 路径不可读直接 `SpecError`。

语义 lint（均 warn 级、消息带实测值）：`markers-on-dense-line`（line 系列带 marker 且单组绘制点数 >50——marker 糊成纹理不再是编码）、`tick-density`（数值轴自动主刻度 >8、类别轴刻度 >12——bar/box/violin 的 x 与 heat 的双轴都算类别轴；显式 `ticks` 的数值轴视为已自控疏密；刻度计数按当前 lim 现算，mpl 的 `nbins="auto"` 会随轴宽自适应，窄轴本身出不了密刻度；计数按刻度位置不按可见标签——`tick_stride` 疏化只去文本不去刻度，疏化后仍告警是设计口径，刻意密轴用 `audit_ignore`/`panel.audit_ignore` 点名 `tick-density` 配对豁免）、`bar-count`（未分组未堆叠柱 >12 根——同形柱墙无从比较）、`hist-bin-sanity`（整数 `bins` 或 edge 数组格数出 5..200 窗口）、`violin-min-points`（任一组数值点 <10——KDE 轮廓对小样本是假精确，建议 `box`）、`kde-min-points`（同口径作用于 kde 系列——小样本密度曲线假精确，建议 `ecdf`/`scatter`）、`heat-cell-text`（heat 开 `annotate` 且任一轴 >20 格——格内字糊成噪声，建议 `annotate:false`）、`log-tick-unlabeled`（`scale:'log'` + 显式非 10 幂 `ticks` + 无 `tick_labels` 时主刻度无标签的提醒——只认 `scale:'log'`；symlog 轴上显式非幂 ticks + 无 `tick_labels` 的渲染口径未验证、lint 不覆盖）、`dodge-single-group`（bar `by` 扇出但每个 x 槽位至多一组有行——宽度仍按组数缩窄、柱体偏离槽位中心，`by`==`x` 字段误用是典型来源，多半该去掉 `by` 改 `labels` 直标）。

`formats:['pgf']` 的审计落差要知道：pgf 产物的文字在宿主 LaTeX 文档里才排版——字号、缺字形、文字出界这类 audit 检查按渲染期的 mpl 度量算，对宿主文档的最终版面只是近似（宿主字体族不同度量就漂）。camera-ready 交付 pgf 时，文字类审计结论置信度打折，几何/数据类不受影响。

pgf 的宿主契约另有一层：落盘按 `pgf.texsystem:'xelatex'` + `pgf.rcfonts:False`——宿主导言最小 `\usepackage{pgf}` 即够，字体命令不进 pgf 流、全部归宿主文档字体族（rcfonts False 的意义）。代价是 spec 文本字段（title/label/note.text/caption）原样写进 LaTeX 源码——裸 `%`、`&`、`#` 会炸宿主编译，`_`/`^` 要走 `$..$` 段或 `\textunderscore` 这类转义；mathtext 段只管数学排版、管不了这层宿主语法。

## colors：项目色层

修的是「多个调色板一家人」漂移：注册表与 ramp 一旦声明，全论文同一实体同一色。

```json
"colors": {
  "registries": {"arm": {"frozen": "vblue", "liveB": "vcoral"}},
  "ramps":      {"top1": {"0.3": "#6BAED6", "0.5": "#3182BD", "0.9": "#08306B"}},
  "extend":     {"ghost": "#6E7378"}
}
```

- `registries: {NAME:{key:color}}`——ARM_COLORS 契约：一个 arm/实体在每张图里固定一色。
- `ramps: {NAME:{level:color}}`——按**真实数值 level** 键控的有序渐变（TOP1_COLORS/BETA_COLORS/LAM_SHADES）；JSON 字符串键按数值归一，`"0.3"`≡`0.3`、`"true"`≡`true`——整数 level 键也直收（`"0"`≡`0`）。

组键 → registry/ramp 键的映射同走 `_norm_key` 归一：数值/布尔等价互命中（组值 `8` 命中键 `"8"`、`'true'`≡`true`），字符串键 verbatim 大小写敏感——`'BERT'`≠`'bert'`。audit 侧 `hue-budget` 的 4 色相预算不把 `vgray` 计入——灰是中性工作马，不耗色相名额。

- `extend: {name:hex}`——裸 hex **唯一**允许出现的位置：声明离板 token。注册与扩展的 hex 全部进 `audit_kwargs.extra_palette`，并入 audit 的 OFFPALETTE 接受色集。

`series[].color` 解析语法（registry/ramp 键缺失 = render error `unresolved-color`，绝不静默落灰）：

| 写法                              | 语义                                                                                      |
| --------------------------------- | ----------------------------------------------------------------------------------------- |
| `"<注册表名>"`（如 `"arm"`）      | 字符串值即注册表名本身——按组值查该 registry，不是字面量 `"registry"`（by-fan-out 的常态） |
| `"<注册表名>:key"`                | 固定取某 key                                                                              |
| `{registry:R, key:k}`             | 同上对象形                                                                                |
| `{registry:R, field:f}`           | 按行/组的字段 f 值查                                                                      |
| `{ramp:R}`                        | 组值作为 ramp level 键                                                                    |
| `"<ramp名>:<level>"`              | ramp 定值引用——对象形 `{ramp:R}` 无 `key`/`field` 子形，固定取某 level 只能走串形         |
| `"parent"`                        | 继承 of-父系列解析出的 per-facet 色（of-子系列默认）                                      |
| `"palette:N"`                     | 主题第 N 色                                                                               |
| `v*` 色相 / `NEUTRALS` / `*_edge` | 调色板 token                                                                              |
| extend 名 / `{key:color}` 内联表  | 扩展色 / 一次性映射                                                                       |
| 裸 hex                            | 合法但 warn（`hex-literal`——能注册就别裸写）                                              |

调色板 token 实名以 `fvstyle.py` 为准：`HUES` = vteal/vorange/vcoral/vviolet/vgreen/vgold/vblue/vrose/vgray——`vgray` 是**色相**，不在 NEUTRALS；`NEUTRALS` = vink/vmist/paper/baseline（`baseline`==vgray，参考线语义别名）；`EDGE` = 同 9 色的 `*_edge` 描边深色。

## data：聚合表

`{name: rows | {columns:{col:[..]}} | {csv:'path'} | {fields:[..], map:{key:row}}}`——只消费**预聚合**数据，spec 永远看不到原始实验状态。硬约束：非中性 kind 的 `needs_data` 恒真——`x`/`y` 给字面量数组也绕不过 `data` 字段（行源仍要一个 dataset 承接 where/by/color-field）；零 dataset 且无 `from` → `SpecError`（`no 'from' and data is ambiguous`），多 dataset 无 `from` 同错。

- `rows`：规范形，`list[dict]` 平铺行。
- `columns`：列存形 `{col: [..]}`。
- `csv`：落盘聚合表，路径相对 spec 文件解析；`DictReader` 读入并做 int/float/bool 强转——落盘 replot 就是经它 round-trip。
- `{fields, map}`（Python API）：把 tuple-key 聚合 dict `res[(arm,lev,K,L)] -> {med,q25,...}` 炸成列。

聚合 helper 收在兄弟模块 `fvagg.py`（纯 stdlib，与 fvspec 同目录经 fvlocate 加载）：`agg_rows(rows, keys, aggs)` group-by 出统计列（`n/mean/median/q25/q75/min/max/std` 或 callable，裸字段名默认 `median`，行序按 key 排序）；`keyed_to_rows(fmap, fields)` 把 tuple-key 聚合 dict 炸成平铺行（`{fields,map}` 的生产端镜像）；`cells_present(rows, x, y)` 列 (x,y) 笛卡尔积的缺席组合（heat 进 spec 前自查缺格）；`add_field(rows, name, fn)` 派生列；`dump_csv`/`load_csv` 落盘 round-trip（cell coercion 与 `{csv}` 入口共用同一函数；csv 无 None 表示——None 写空串读回 `''`，含 None 的列走 rows/columns 形）。分位数用 `statistics.quantiles(method='inclusive')`，与 `np.quantile` 默认线性法一致。诊断/派生层：`pareto_front(rows, x, y, senses, by, mark)` 两目标支配过滤（默认产 `on_front` 布尔列——一份数据同时喂散点分色与 `where:{on_front:true}` 前沿折线，`draw:'steps-post'` 配 min-x 前沿）；`calibration_bins(rows, conf, acc, bins, strategy)` 可靠性分箱（等宽/等质量、bin-mean/bin-center 两种 x 约定，顺带 ECE/MCE）；`jitter(rows, col, by, amount, seed)` 物化抖动坐标列（strip/raincloud 点层，按组独立随机流、组间增删行稳定）；`rank(rows, col, by, order, ties)` 组内名次列（bump 图，ties 收 min/dense/first/average）。全部纯函数返回新行副本，数值字段遇 float NaN 一律响亮报错。仓外用法把 `fvlocate.py` 拷到脚本旁再 `import fvlocate; fvlocate.ensure()`——注意 vendored 副本被 import 时会在产物目录留 `__pycache__/`，交付前自清。

## layout — matrix

`kind:'matrix'` = ggplot `facet_grid` 的 spec 化：`template` 面板 × `rows`/`cols` facet 值展开成面板矩阵——不再手写 N 份只差一个 where 条件的 panel。顶层不收 `panels` 与面板字段（`legend` 例外——它只有 figure 语义）；模板里的显式 series `id` 按格加面板前缀（同格 `of` 引用同步改写）。

| 字段          | 含义                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rows`/`cols` | facet 声明：值列表 `['A','B']`、对象形 `{values:[..]}` 显式钉 facet 序，或 `{field:'g'}` 从 `template.from`（数据唯一时省 `from`）派生 distinct 值——数值可排则升序、否则首见序（`field` 与 `values` 同给时 `values` 赢）；`{labels:{值:显示文本}}` 换 strip 文本（where 仍用原值，与取值源自由组合）；`{strip:false}` 关该侧 strip。两边至少给一边；缺的一边退化成单列/单行，不加 margin。模板里出现 `$row` 而 `rows` 缺席 → `SpecError`（`$col` 同）                                                                                    |
| `template`    | 一个 panel spec（panel 键全收）。`$row`/`$col` 代入三形态：整串 `'$row'` → **保类型**的 facet 值（`where:{g:'$row'}` 里 int 仍是 int）；字符串内嵌 → 文本插值（`title:'$row arm'`、字段名 `'y_$col'`）；dict 键 → 文本替换。facet `field` 自动注入每条数据绑定 series 的 `where`（中性 ref/span/note 与直给 `matrix`/`path`/`rgb` 的数据自由系列不注入——渲染期 needs_data 同口径）；`of` 子系列不写 `where` 时继承父级注入。panel.where/series.where 与 facet 值同文合法、异文 `SpecError`——strip 文本与注入条件同源，漂移在构造上不可能 |
| `overrides`   | `{cell: patch}` 逐格补丁：键 = 自动 id `'<行值>-<列值>'`（slug 化）或位置 `'r,c'`；值 = `null`/`false` 空格、字符串命名格（axis-off，图例 `where:'cell'` 目标，闲置吃 `dead-cell` lint）、对象面板补丁（顶层键替换，dict 值如 `xaxis`/`where` 浅合并一层）                                                                                                                                                                                                                                                                               |
| `strips`      | strip margin 位置 `'top'`\|`'right'`\|`'both'`（默认，现状）\|`'none'`——整体收编两侧边缘格（贴边排版/手动挂 strip 文本时收）；per-edge `{strip:false}` 管单侧开关与样式，`strips` 管位置存在性，组合照常（grid/spans 上写 `SpecError`）                                                                                                                                                                                                                                                                                                  |

strip margin：facet 标签住在 gridspec 边缘格（顶=列、右=行）——`strip` 是 facet 标签不是面板标题，`tag` 角标仍走 title slot 互不占用；`{fmt:'{l}'}` 模板 `{f}`=字段名 `{l}`=labels/原值 `{v}`=原值、`{bbox:true\|false\|{...}}` 默认 vmist 底、`{size:0.22}` margin 占比。`layout.strips:'top'|'right'|'both'(默认)|'none'` 管两侧边缘格的存在性——`'top'`/`'right'` 单边收掉另一侧 margin（matrix 贴边排版），`'none'` 两侧全收。密度上限 24 格/边 8（全 image 图版同 grid 放宽 64/16）。

## layout — spans

`kind:'spans'` = gridspec 跨格矩形：`map:{panel-or-cell-id:[r0,c0,r1,c1]}` 半开区间。`shape` 可省（按 rect 最大边界推断），显式 `shape` 须含全部 rect。rect 两两不相交、panel 必须全部落位，否则 `SpecError`。逻辑网格是比例尺不是面板密度——面板数仍按 8 收（图版 64），但命名 map 键是占格不是面板、不占名额（8 面板 + 图例格塞 3x3 地图合法）；网格边长放到 8（joint 3:1、clustermap 侧条够表达）。tag 序按 (r0,c0) 视觉序。命名 map 键 = axis-off 格（图例 `where:'cell'` 目标，闲置吃 `dead-cell` lint）。map 未覆盖的网格区域是合法空格——不物化 axes、不触发 `dead-cell`（该 lint 只咬命名了又闲置的 axis-off 键）。`size` 只给 slot 时高度 = 1.8in×逻辑网格行数（map rect 最大 r1）——joint 的 3 行 map 默认 ~5.4in，紧凑排版须显式 `size.height`。

`bind:{side:{to, axis:'x'\|'y'}}` 边际轴配对：side 的绑定轴经 `sharex/sharey()` 并入 main 共享组（viewlim 联动），side 绑定轴的刻度标签与轴标签隐藏；side 是 main 的边际装饰——`missing-axis-label`/`legend-coverage` 两轴豁免、边默认不发标签（joint marginal、clustermap 侧条/树状图语义）。side/main 必须都是 `xy` 面板、不可自绑；side 在绑定轴上声明 label → lint `axis-ignored`。边际分布：分布 kind 在 side 面板里用 `dir:'h'` 横置——hist/kde/ecdf 数据落绑定轴对面的轴（`axis:'y'` 右侧边际时数据在 y、量沿 x），box/violin 数据沿 x、组位置沿 y（`axis:'x'` 顶部边际，`axis:'y'` 侧条维持缺省竖置即可）。

```yaml
# joint：上方 x 边际 hist + 主散点 + 右侧 y 边际
layout:
    kind: spans
    map: { hx: [0, 0, 1, 3], main: [1, 0, 3, 3], hy: [1, 3, 3, 4] }
    bind: { hx: { to: main, axis: x }, hy: { to: main, axis: y } }
    cols: { xlabel: sepal length } # 只发到底缘 main，marginal 不领
    rows: { ylabel: sepal width }
    width_ratios: [2, 2, 2, 1]
    height_ratios: [1, 2, 2]
```

heatmap 是 F 族主 kind：confusion/correlation/win-rate/sensitivity 全走它。场族 `contour`/`quiver` 与 heat 共享 `cmap`/`vcenter`/`cbar` 三件套与 mist 缺格约定，但 x/y 是真实数值坐标轴（非 heat 的类别格轴）——loss landscape、梯度/流向场、speed field 这类「场上的函数」走它们；一条场系列就是一个场，`by`/`of`/`color` 不适用（cmap 就是色载体），也不进 radar 面板。场默认 zorder 0.5 垫在数据系列（≥1）之下，叠加散点/轨迹不遮；`contourf` 与 `pcolormesh` 同属不透明覆盖面，压在更低 zorder 的对象上触发 `occluded-by-heat`。

`image` 是图版 kind：方法×样本示例墙（layout 网格放宽见 `shape`/`cells`）与 heat 叠图底图走它——一条 image 系列逐行一张图，`by`/`of`/`color` 不适用（像素自带颜色，标量场交给 `cmap`），也不进 radar 面板；默认 zorder 0 垫在一切之下。纯 image 面板（含中性 overlay 不算杂）的轴刻度默认收掉、`grid` 默认 `none`、`frame` 默认 `closed`（spine 当 cell 边线）——显式 `xaxis`/`yaxis.ticks`、`grid`、`frame` 均可钉回；audit 侧 `ax.images` 已算内容承担者：纯像素轴不再被 `missing-axis-label`/`facet-ylim-mismatch` 索量纲，badge 角标不吃 `text-overlaps-data`/`low-contrast`。

`sankey` 是流图 kind：数据流/样本筛漏斗/能量分配这类「守恒拆分与汇合」走它——聚合成长表（src,dst,value）喂进来，或 `flows` 字面流直给（小图免建 dataset），列布局、守恒校验、缎带几何全在 kind 层；跨列长流缎带垫在中间列节点条之下（d3 惯例）。`dir:'v'` 把列布局竖过来（stage 自上而下成行、行内流自左向右堆叠，漏斗/流程图纵向阅读序）。面板坐标是流量单位不是数据轴，故一条 sankey 独占 panel、刻度归 `NullLocator` 收掉（幻影 tick-label 是 readback 已知坑，不用 `axis('off')`）、全部 artist 标 fv-neutral——`missing-axis-label` 等数据轴语义规则自然不适用，无需 `audit_ignore`；用户 `xaxis.lim`/`label` 仍是加宽标签通道与挂量纲的逃生口。

`note` 行扇出（`at:{x,y}` dict 形）的两个标准用法——`{field}`/`{field:fmt}` 模板只在扇出形下按行展开，标量 `at` 的 `text` 原样渲染不替换：

- stats inset：`{kind:'note', from:'stats', at:{x:0.03, y:0.97}, units:'axes', text:'ECE={ece:.3f} · MCE={mce:.3f}', props:{ha:'left', va:'top'}}`——单行 stats 数据集 + axes 坐标扇出一条。
- 轴外文本列：`{kind:'note', from:'est', at:{x:1.03, y:'yrow'}, units:['axes','data'], text:'{est:.2f} [{lo:.2f}, {hi:.2f}]', props:{ha:'left', va:'center'}}`——`units` 按分量各自生效：x 字面量逐行广播钉在轴外通道、y 走数据列（forest 右侧 est(CI) 栏）。

## legend（图级）

`{where:'below'|'cell', cell:<cell-id>, loc, ncol, fontsize, title, columnspacing, handletextpad, labelspacing, props, from:[panel-ids], entries:[..]}`

- `below` → `fig.legend(loc='lower center')` + `arrange.rect` 留出底部空间（多条合成条目）；`cell` → axis-off gridspec 格（如 2 行网格的 `gs[1,0]`）。`loc` 取 mpl loc 字符串（`'upper right'` 等，panel legend 同口径）。
- `entries`：与所画 series 1:1 解耦的显式有序表——`{series:id}` 克隆一条已画系列的样式+label（by 扇出系列只克隆 `groups[0]` 一条）；`{group:id, label:'模板 {field}'}` 整组按组序逐条发、各取解析色（按 level 逐条发色块）；`{handle:{label,color,ls,marker,lw,ms}}` 幽灵句柄给没有画出系列的样式角色（`'solid=exp dashed=W'`）。粒度到「整条系列 / 整个组」为止——只挑组里某一条、或把独立系列插进组序列中间都表达不了，自由编排一律 `{handle}` 手写（幽灵句柄固定产 Line2D——`{kind:'patch'}` 无一等支持，bar 组的幽灵色块退化成线柄）。
- mpl 按**列主序**填 `ncol` < 条目数的图例——ncol=3、六条目时第一行是 E0,E2,E4；想要行主序阅读，把 `entries` 按列读序排（或干脆 `ncol:1`）。
- `entries` 缺省 → 自动收集 `from` 面板的有 label artist，`from` 默认 = **没有自己 legend 的面板**——混合计划不双计数，同 label 文本跨面板自动去重；收集序跟随 spec series 声明序（面板内按 rec 序、组内按组序逐条认领；connect 幽灵句柄等未认领项按 mpl 序殿后），要任意编排仍钉 `entries`。
- 扁平形（无 `panels`）里的顶层 `legend`：带 `where`/`cell`/`from` 任一图级键 = 图级 legend；否则 = 该单面板的 panel legend。
- `empty-legend` 的触发口径：不是「图上没图例」就报——声明了图例却收不到句柄才报，三处：图级 legend 收集零句柄、donut `labels:'legend'` 无图例收、`connect.label` 无图例收；面板 legend 声明后零句柄回落 mpl 原生 no-artists 警告，不进 lint 通道。
- 图例句柄的 marker 大小不跟随 scatter 的 `s`（mpl 原生——句柄取默认大小）；要表达点径差异走就地文字或幽灵句柄说明。
- 单系列柱要「每柱一色 + 柱名图例」无 spec 直路：`by` 扇出触发 dodge（且每槽一组吃 `dodge-single-group` warn），拆 N 条 series 进图例又太重——`labels` 就地标名代替图例是现行出口，或 `raw` 自绘。bar 无 per-row 颜色通道（field-resolved 色组内不唯一即 `SpecError`）——瀑布正负增量分色走 `raw` 重刷 patch：`for p, r in zip(ax.patches, ctx['data']['w']): p.set_facecolor(ctx['fv'].HUES['vcoral' if r['v']<0 else 'vteal'])`（token 字面量在 raw 不解析，须 `ctx['fv']` 取真色）。

## 边界

`render(spec)->Figure` 是 spec + 引用 CSV 的纯函数：

- presence-conditional series → 预过滤行（`by` 的稀疏语义），不写 `if key in dict`；
- 数据派生的注释几何 → 解析后的值（`note.at`、`ref.at` join），不算坐标；
- 数值/求解器/模型加载/多段 CSV/env 缓存 → 脚本 glue；
- 多图脚本 → 一图一 spec；
- 全自由构图（机制示意）→ 纯 matplotlib + fvstyle token，audit 照跑。
